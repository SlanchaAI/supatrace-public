Security

What is in place.
What is not.

Traces can contain prompts, tool output, personal information and secrets. This page states only what can be checked in the SupaTrace deployment template and source, and lists plainly what does not exist yet.

SupaTrace holds no security certification. There is no SOC 2 report, no ISO 27001 certificate, no HIPAA program and no DPA. It is a small alpha: use synthetic or deliberately reviewed data.

Where data lives

  • One AWS region. The service runs in AWS us-east-1 from one CloudFormation stack: CloudFront, a Lambda function, S3 buckets and a DynamoDB table.
  • Trace payloads are stored as objects in a private S3 bucket. Metadata (accounts, sessions, keys, trace indexes) is stored in DynamoDB.
  • No public buckets. Both S3 buckets block all public access; CloudFront reads the static bucket through origin access control.

Encryption

  • At rest: the S3 buckets use server-side encryption with Amazon S3 managed keys (SSE-S3, AES-256), and the DynamoDB table has server-side encryption enabled. Keys are AWS-managed; there are no customer-managed keys.
  • In transit: CloudFront redirects HTTP to HTTPS, requires TLS 1.2 or later (policy TLSv1.2_2021) and sends HSTS for one year. The API origin is HTTPS only.

Sign-in and access

  • Sign-in: GitHub OAuth, and Google OAuth where configured. The first sign-in with Google or GitHub opens an existing account when both providers verify the same email address; that verified address is stored on the account to decide this. Accounts that already exist stay separate unless their owner links them. Linked sign-in methods are listed in Settings and can be unlinked. SupaTrace does not store a password or a provider token for these sign-ins.
  • Sessions: the session cookie is HttpOnly, Secure and SameSite=Lax, and the server stores a SHA-256 digest of the session token, not the token.
  • Ingest keys are write-only. An ingest key (st_pub_…) can upload to one project and environment and cannot read traces. It does not expire unless you set an expiry, and it can be rotated or revoked. Keys made with a setup code are also write-only and expire after 30 days. A secret key (st_sec_…) can also read the traces of its own workspace and environment, so keep it on a server. The server stores a SHA-256 of each key, not the key. See Keys.
  • Roles: workspace owners can invite existing accounts as Admin, Developer or Read-only, with plan-gated roles and environment scopes. Enterprise supports custom roles.
  • Browser hardening: pages are served with a Content-Security-Policy that allows only same-origin scripts and styles, X-Frame-Options DENY, nosniff and no-referrer.

Your data

  • Explicit capture. Manual uploads send only the batch files you chose. Two paths store data without a per-batch review, and only after you opt in: the Claude Code hook beta uploads the events it captured when Claude completes if you enabled --upload-on-stop for that spool, and the Langfuse import stores the exact scope you reviewed. Nothing searches your disk or tails transcripts.
  • Export: you can export a trace, an environment or a workspace as JSON. Exports are not redacted. See Export.
  • Logs: application logs are kept for 7 days.

Boundaries and unavailable features

  • SOC 2: no report and no audit under way. No auditor or target date has been chosen.
  • ISO 27001: none.
  • HIPAA: not supported. No BAA is offered. Do not send protected health information.
  • DPA: none available.
  • Terms of service and privacy policy: read the Terms, Privacy Policy, Acceptable Use Policy and Subprocessors.
  • Penetration test: no third-party test report.
  • Security contact and disclosure policy: report security concerns to security@supatrace.dev. No security.txt or bug bounty is published.
  • Deletion: individual-trace deletion is unavailable. Self-service account, organization, project and environment deletion revoke access and queue physical erasure. Retention is 7 days on Free (longer on paid plans), counted from when a batch is accepted: expired data is hidden immediately and the scheduled worker erases payload versions. Data stored before retention existed has no expiry and stays readable. DynamoDB point-in-time backups expire within 35 days.
  • Multi-factor authentication and SAML single sign-on: MFA is enabled on supatrace.dev; Enterprise SAML login and enforcement have live acceptance. The repository template leaves MFA disabled until the operator enables it.
  • Audit log and SCIM: Pro includes audit viewing; Enterprise adds audit export and SCIM provisioning. Both have live acceptance. Customer-managed keys and region choice are unavailable; no uptime SLA is offered without agreed contractual terms.

The Enterprise page tracks which of these are planned.
