Keys

Ingest keys from the Home card or API keys page do not expire by default; keys from pairing an agent last 30 days.

There are three kinds of key. An ingest key sends traces and cannot read them. A secret key also reads. A setup-code key is the older write-only key that an agent requests and you approve.

Ingest keys and secret keys

Create these in your workspace: Create ingest key and show snippets on Home makes an ingest key in one click, and API keys makes either type. Your browser generates the key and sends the server only its SHA-256, so the key is shown once and cannot be recovered.

  • Ingest key (st_pub_…). Write-only. It can upload batches, OTLP spans and Langfuse SDK events to its project and environment. It cannot list, read or export traces.
  • Secret key (st_sec_…). Writes, and reads the traces and events of its own workspace and environment through GET /api/v1/traces and /api/v1/traces/{id}/events. It cannot read usage, list keys, workspaces or projects, or reach another workspace or environment. Keep it on a server.
  • No expiry by default. You can choose 30 days, 90 days or 1 year under API keys. The Home card's key has no expiry.
  • Rotate. Rotation issues a replacement and keeps the old key working for an overlap window (24 hours by default) so you can deploy the new one.
  • Revoke. Revoking stops new uploads at once; it does not delete stored data.

Send a key as x-supatrace-key: KEY or Authorization: Bearer KEY.

Setup-code keys

Run connect.py from the setup guide. It creates the key on your machine and shows a 12-character setup code. Approve only the code your own terminal just showed you, under Agents in your workspace. Setup codes expire after 10 minutes.

python3 connect.py --project YOUR_PROJECT_ID --config ./supatrace-access.json
Scroll for more →

The script saves the credentials to the config file you chose, with owner-only permissions. Never commit that file or paste it into chat.

What a setup-code key can do

  • Write-only. A key can upload batches to its project. It cannot list, read or export traces.
  • 30 days. Setup-code keys expire 30 days after approval. Make and approve a new connection to continue, or use an ingest key, which does not expire by default.
  • Revocable. Revoke a key under API keys in your workspace. Revoking stops new uploads; it does not delete stored data.
  • Up to 10 active keys for a project, of all kinds together.

Not available yet

  • Write operations in the management API. A personal access token, created under Settings in your workspace, can read workspaces, keys, usage and traces through /api/v1; the API describes itself at /api/v1/openapi.json.

The first sign-in with Google or GitHub opens your existing account when both providers verify the same email address. A provider that does not report a verified address gets its own account, and accounts that already exist stay separate unless you link them. Linked sign-in methods are listed under Settings, where they can be unlinked.

Keys in the preview SDK

The SDK reads SUPATRACE_API_KEY only for OTLP export, and the hosted OTLP/HTTP receiver accepts traces today. The Python SDK is Beta on PyPI (supatrace 0.1.0); the JavaScript package is Coming soon on npm. For the hosted first-trace path, use a stock exporter. Source mode needs no key: it writes local files that you upload with upload.py and your config file.
