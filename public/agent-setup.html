Explicit capture · small alpha

Your first trace.

1. Home: create an ingest key and run a curl, Python or Node snippet (about 30 seconds after sign-in). 2. Send OTLP from any OpenTelemetry exporter. 3. Use the reviewed scripts below when an agent needs approval.

Ingest keys from the Home card or API keys page do not expire by default; keys from pairing an agent last 30 days.

Path 3: reviewed scripts

You need Python 3, a terminal and a SupaTrace sign-in. The scripts use Python's standard library; no package install is needed.

Traces may contain prompts, tool output, personal information and secrets. Review what you select and remove anything you do not intend to store. The manual steps below do not scan your machine, install hooks or upload automatically. The separate Claude hook beta requires explicit project installation and content/upload choices. Automatic Codex capture is not available.

1. Download the three scripts

Save these together in a new folder, then open your terminal in that folder. Read the scripts before running them.

connect.py ↓upload.py ↓claude_snapshot.py ↓

The connection and snapshot scripts import upload.py, so keep all three together.

2. Approve a write-only connection

Open Agents in your workspace. Copy its project-specific command, or replace YOUR_PROJECT_ID below with the project ID shown there.

python3 connect.py --project YOUR_PROJECT_ID --config ./supatrace-access.json
Scroll for more →

The script creates a key locally and shows a 12-character setup code. Approve only the code your own agent just showed you. Once approved, the script saves write-only credentials to your selected config file with owner-only permissions.

Keep that config private. Never commit it or paste it into chat. The key lasts 30 days, cannot read traces and can be revoked in API keys. Return with the same sign-in provider, or one linked to the account: a Google and a GitHub sign-in open the same account only when they are linked, which happens at a first sign-in when both verify the same email address or by your choice in Settings.

3. Send the reviewed synthetic example

Download first-trace.json into that folder and inspect it. It contains three synthetic events and no real transcript data. Then explicitly upload it:

python3 upload.py ./first-trace.json --config ./supatrace-access.json
Scroll for more →

Wait for Accepted by server. The uploader keeps a local pending copy until the server returns the matching batch ID, byte hash and project ID. A failed or ambiguous response leaves it pending. Follow the specific recovery message: rate limits require waiting, capacity or key failures require review, and an unconfirmed outcome requires batch/hash/project reconciliation before another explicit attempt. Do not change a batch ID to force a retry. Server reservations may remain even when no acknowledgment arrives. Repeating this exact example is idempotent, not a second run.

4. Inspect and export

Open Traces, select Refresh, then open first-trace-example. Compare the event contents with your example. Use Export original JSON for every accepted batch in that trace, independently of how many batches are shown. Save File support streams to disk; other browsers are limited to 20 MiB and 100,000 events per trace. Original exports are not automatically redacted; review the complete file before sharing. The optional Prepare redacted copy control masks selected paths and exact text locally, requires a reviewed preview, and does not guarantee anonymity. It does not change stored traces or original exports. The local redacted preview has a 2 MiB input limit. Identifier masks can break links or merge distinct IDs; read the impact report before sharing.

Export account reads every indexed trace in this project, not just the filtered table. Account archives are not redacted and may contain secrets or personal information. Review the complete archive before sharing; the per-trace redacted-copy tool does not redact it. Exports preserve event fields, not original uploaded batch bytes. Save File support streams the archive to disk. Other browsers prepare a standard download limited to 20 MiB total (including metadata) and 100,000 events across all traces. When ready, choose Download account archive, then check your browser downloads to confirm it saved. Discard prepared archive releases the local copy. Pause uploads during preparation: the app compares fresh catalogs before and after, but this is an observed read, not a point-in-time snapshot.

5. Try a selected Claude Code snapshot

When the example works, choose one finished transcript yourself. The converter never searches your disk. Use a unique run ID and a clean output folder for each snapshot:

python3 claude_snapshot.py /path/to/selected-transcript.jsonl --run-id my-reviewed-snapshot --out ./reviewed-batches

Inspect every generated batch before uploading. The summary counts unsupported blocks or rows rather than claiming they were captured. Oversized blocks fail instead of being silently truncated. Upload reviewed batches one at a time in numbered filename order:

python3 upload.py ./reviewed-batches/BATCH.json --config ./supatrace-access.json

Do not mix old and new conversions under a reused run ID. Events within batches preserve their order; batches are exported in server acceptance order. Upload source chunks in order when that sequence matters.

Optional: Claude Code hook beta
This separate opt-in connector receives prompt-submission, successful-tool and completion events from Claude through stdin. It does not read session files or install itself. Native installed-version and hosted acceptance are not yet verified. This is partial hook coverage, not a complete model trace; interruptions, failed tools and API errors are not captured.
On macOS or Linux, save claude_hook.py beside upload.py, outside the source project. Use the existing approved private connection config. Choose an exact source workspace and a new private spool outside it:
python3 claude_hook.py init --workspace /absolute/source/project --config /absolute/private/supatrace-access.json --spool /absolute/private/new-hook-spool
Scroll for more →
The default keeps metadata only and does not upload. To retain prompts, tool arguments/results and final text, initialization requires both --content --allow-content. That content may contain secrets, personal information and file paths; it is not redacted. Separately add --upload-on-stop only if you approve automatic bounded uploads to that config's project when Claude completes. These choices are fixed for this spool. Do not put the config or spool in your repository.
Review the project settings example. Replace its absolute Python, script and spool paths; preserve JSON quoting. With explicit permission, merge only those entries into this project's .claude/settings.local.json, preserving existing hooks. Do not replace user-wide settings, add async execution or blocking decisions. The example sets a twelve-second timeout. First use a deliberately nonsensitive session and verify the installed version actually provides session_id, prompt_id and tool IDs. Missing fields are omissions, not a reason to read transcripts.
python3 claude_hook.py status --spool /absolute/private/new-hook-spool
python3 claude_hook.py flush --spool /absolute/private/new-hook-spool
Scroll for more →
Flush explicitly sends pending data to the approved config's project. It allows at most two requests with an eight-second interrupt deadline and a twelve-second host hook timeout. Some library calls can delay Python signals; installed timeout behavior needs verification. Larger backlogs may remain pending. Matching batch/hash/project acknowledgments count as accepted, not verified hosted readback. Inspect the actual trace in your workspace. Uncertain uploads block further sends until authenticated reconciliation; do not blindly retry, delete the journal or recreate keys. Stop events use local occurrence IDs, so duplicate Stop delivery can remain duplicated.
Capture is bounded to 2,000 events / 8 MiB of journal and 24 MiB of private spool including write reserve. No automatic rollover or deletion. Health output counts omissions where it can; lock/disk failure can prevent even that marker. To stop capture, remove only the project hook entries you added. Revoke only the intended key to stop acceptance; this does not delete stored or pending data. Real agent capture and saved export verification remain separate acceptance steps.


Current limits
  • Organizations support multiple isolated projects within plan limits (Free 2, Base 3, Pro 10, Enterprise 20). Owners invite existing accounts and assign plan-enabled roles and environment scopes. Google and GitHub identities can link when their verified email matches.
  • Free allowance: 50,000 spans per UTC calendar month and 1 GB stored per organization, shared across its environments and including accepted and pending uploads. A span is one accepted event. The span count resets on the first of each month. Stored bytes are cumulative: storage does not reset monthly.
  • Shared service caps can stop an upload before an organization reaches its own allowance. Contact support if a service cap blocks your paid plan.
  • 1–100 events per batch; 512 KiB per batch; 32 KiB per event's JSON data; nesting depth 32.
  • 60 API requests per minute per network; 30 uploads per minute per account. Shared networks may share the request limit.
  • Up to 2 active write keys on Free (10 on Base, 25 on Pro, 100 on Enterprise), expiring after 30 days. Setup codes expire after 10 minutes.
  • Claude snapshot input at most 20 MiB. Finished explicit snapshots only, not a live tailer.
  • Trace listing follows the complete catalog within 100,000 run IDs, 20 MiB of metadata and five minutes per scan. Filters and totals cover that completed catalog. If a scan fails or reaches a limit, no partial total is presented as complete; retry Refresh.
  • Base and Pro are monthly subscriptions per organization, billed through Stripe. Expired traces are hidden immediately; the scheduled retention worker removes their payload versions and releases stored-byte capacity. Retention defaults are Free 7, Base 30, Pro 90 and Enterprise 365 days.


When something goes wrong
  • Sign-in failed or expired: start a fresh sign-in from the workspace with the same provider. Do not refresh or share an OAuth callback URL.
  • Setup expired: no key is granted by that response. Keep the selected pending config private and unchanged; use a different config path for a new setup. Approved configs are not silently replaced.
  • Key expired or revoked: explicitly make and approve a new connection. Do not overwrite another project's config.
  • Rate limit: keep the local batch unchanged and wait for the retry window. Export can pause and retry. Cancel is available during preparation, before final saving or download begins. After a standard download starts, use your browser downloads to manage it.
  • Allowance or capacity reached: your pending batch remains local. The monthly span count resets on the first of the month (UTC); stored bytes do not reset, and repeated uploads cannot add capacity. Pending server reservations also consume quota.
  • Network loss: keep the original transcript and pending file until you verify the accepted trace. Local spooling survives process exit, not a lost machine or disk.
Settings provides account closure; organization, project and environment deletion queues physical erasure after a ten-minute in-flight grace period. Account closure requires transferring or deleting owned organizations first. An individual trace has no delete control. Recovery backups expire within 35 days.
