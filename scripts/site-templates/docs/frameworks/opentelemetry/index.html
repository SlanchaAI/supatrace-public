OpenTelemetry

Send OpenTelemetry traces to supatrace.dev over OTLP/HTTP using stock Python or Node exporters. Protobuf and JSON supported; no gRPC, metrics or logs.

Python SDK: Beta. JavaScript SDK: Coming soon. Install the alpha Python package with pip install supatrace==0.1.0 (Python 3.10+). The JavaScript supatrace package is not published to npm; its examples run from the public repository root. For a first hosted trace, use the stock OpenTelemetry exporter or the Python/Node snippets on Home.

OTLP/HTTP ingest Live

SupaTrace accepts OpenTelemetry traces at POST /v1/traces on supatrace.dev. Any OTLP/HTTP exporter can send traces with two environment variables and an ingest key; no SupaTrace package is needed.

  • Encoding: protobuf or JSON, with or without gzip. gRPC is not supported.
  • Signals: traces only. Metrics and logs are not served.
  • Size: 512 KiB per request on the wire, 2000 spans and 50 traces per export, 32 KiB stored per span.
  • Storage: each trace becomes a run named otlp.<traceid>. Each span becomes an event. Retried exports store nothing twice.

SDK availability

The SDKs contain the client side. With mode="otlp" they send POST <SUPATRACE_OTLP_ENDPOINT>/v1/traces with the write key, and only when the endpoint, the key and the OpenTelemetry packages are all present. The SDKs have not been run against the receiver.

pip install "opentelemetry-sdk>=1.27" "opentelemetry-exporter-otlp-proto-http>=1.27"
export SUPATRACE_OTLP_ENDPOINT="https://supatrace.dev"   # SupaTrace SDK OTLP mode (Python Beta; JavaScript source only)
export SUPATRACE_API_KEY="YOUR_WRITE_KEY"
import supatrace

trace = supatrace.init(service="checkout", mode="otlp")
trace.span("checkout.step", {"cart.items": 3})
print(trace.capture["sending"], trace.capture["skipped"])
trace.close()
import { init } from "supatrace";

const trace = init("checkout", { mode: "otlp" });
trace.span("checkout.step", { "cart.items": 3 });
console.log(trace.capture.sending, trace.capture.skipped);
await trace.close().shutdown;

Without an endpoint nothing is sent and nothing is saved: in OTLP mode span returns an in-memory batch with no file, and it is gone when the process exits. To get a file you can review and upload, use source mode as in the quickstart. An endpoint in the environment alone never turns export on; mode="otlp" must be explicit.

Apps on a Langfuse SDK Beta

An app that already uses a Langfuse SDK can send its traces to SupaTrace by changing the host and keys. This is ingest only, not a Langfuse API. Score events sent through batch ingestion are stored as events on the trace, but they are not aggregated or shown as scores. The standalone scores endpoint, prompts, datasets and the trace-reading APIs are not served and answer 404. Hosted routes answer on supatrace.dev. SDK acceptance receipts are local only, so Langfuse SDK compatibility remains beta.

export LANGFUSE_HOST="https://supatrace.dev"        # LANGFUSE_BASEURL for the JS SDK
export LANGFUSE_PUBLIC_KEY="pk-supatrace"            # any non-empty value; not a credential
export LANGFUSE_SECRET_KEY="YOUR_WRITE_KEY"

Update events are stored as their own events and are not merged into the observation they update. It was tested with the Langfuse JS SDK 3.39.2 and Python SDK 5.2.0; other versions are untested.

Traces can contain prompts, tool output and secrets. Review before upload.
