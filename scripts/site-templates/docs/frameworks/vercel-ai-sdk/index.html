Vercel AI SDK

Record Vercel AI SDK calls as SupaTrace events from Node.

Python SDK: Beta. JavaScript SDK: Coming soon. Install the alpha Python package with pip install supatrace==0.1.0 (Python 3.10+). The JavaScript supatrace package is not published to npm; its examples run from the public repository root. For a first hosted trace, use the stock OpenTelemetry exporter or the Python/Node snippets on Home.

Record a call in source mode Coming soon

Source mode is the default. It makes no network request: you choose the events, the SDK checks them against the same batch rules the server applies and writes one file to a local spool for you to review. The example records the model name and token counts, not the prompt or the reply.

npm install ./packages/supatrace-js   # from the public repository root. Node 22 or later, ESM only
import { init } from "supatrace";
import { generateText } from "ai";
import { openai } from "@ai-sdk/openai";

const trace = init("support-bot", { spool: "./spool" });
const started = new Date().toISOString();
const { usage } = await generateText({ model: openai("YOUR_MODEL"), prompt: "Say hello." });
const result = trace.batch([
  { id: "req-1", time: started, kind: "request", name: "generateText", data: { model: "YOUR_MODEL" } },
  { id: "res-1", time: new Date().toISOString(), kind: "response", name: "generateText", data: { totalTokens: usage.totalTokens } },
]);
console.log(result.report.valid, result.report.path);

The SDK reads and writes local files, so run it in a Node runtime such as a route handler or server action, not in the Edge runtime or the browser.

Review, then upload

Open the spooled file and read it. Remove anything you do not intend to store. Then upload it with the script from the setup guide, using the write-only connection you approved there:

python3 upload.py ./spool/BATCH.json --config ./supatrace-access.json

The trace appears under Traces in your workspace. Batch limits apply: 100 events and 512 KiB per batch.

AI SDK telemetry over OTLP Coming soon

The AI SDK can emit OpenTelemetry spans through a tracer you pass in its telemetry settings. With mode: "otlp", an endpoint, a key and the OpenTelemetry packages installed, the SupaTrace handle exposes such a tracer as trace.tracer. SupaTrace accepts OTLP/HTTP traces on supatrace.dev. This JavaScript SDK tracer hand-off has not been run against the receiver. Its npm package is Coming soon; source examples use the public repository. Use a stock exporter from the OpenTelemetry guide today.

npm install @opentelemetry/sdk-trace-base @opentelemetry/exporter-trace-otlp-http @opentelemetry/resources
export SUPATRACE_OTLP_ENDPOINT="https://supatrace.dev"   # SupaTrace SDK OTLP mode (Python Beta; JavaScript source only)
export SUPATRACE_API_KEY="YOUR_WRITE_KEY"
import { init } from "supatrace";
import { generateText } from "ai";
import { openai } from "@ai-sdk/openai";

const trace = init("support-bot", { mode: "otlp" });
console.log(trace.capture.sending, trace.capture.skipped);
await generateText({
  model: openai("YOUR_MODEL"),
  prompt: "Say hello.",
  experimental_telemetry: { isEnabled: true, tracer: trace.tracer },
});
await trace.close().shutdown;

When the endpoint, the key or a package is missing, trace.capture.sending is false, trace.tracer is not set and trace.capture.skipped says why.

Traces can contain prompts, tool output and secrets. Review before upload.
