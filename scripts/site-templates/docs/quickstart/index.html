Quickstart

Your first trace

Start with Home: one ingest key and a curl, Python or Node snippet, about 30 seconds after sign-in. Next, send OTLP from any OpenTelemetry exporter. Use the reviewed scripts when an agent needs approval. The Python SDK is on PyPI; the JavaScript npm package is Coming soon.

1. Send a trace from Home Live

  1. Sign in. A new workspace shows Send your first trace on Home.
  2. Select Create ingest key and show snippets. Your browser makes an ingest key (st_pub_…) and sends the server only its SHA-256. The key is shown once, filled into curl, Python and Node snippets.
  3. Run one snippet. It posts a small synthetic chat call to /api/batches and needs no package install.
  4. The card shows the trace when the upload is accepted. Open it from there.

The ingest key can only send traces. It does not expire; revoke or rotate it under API keys. Ingest keys from Home or the API keys page do not expire by default; keys from pairing an agent last 30 days. See Keys.

2. OTLP from any OpenTelemetry exporter Live

Send traces to supatrace.dev over OTLP/HTTP with protobuf or JSON. No SupaTrace package is needed. No gRPC, metrics or logs. See the OpenTelemetry guide for limits.

3. Send a trace with the reviewed scripts Live

You need Python 3, a terminal and a SupaTrace sign-in. The setup guide has the script downloads, the full steps and the recovery notes. In short:

  1. Sign in, open Agents in your workspace and copy your project ID.
  2. Download connect.py, upload.py and first-trace.json from the setup guide into one folder. Read them before running them.
  3. Create a write-only connection. The script shows a 12-character setup code; approve only that code in your workspace.
    python3 connect.py --project YOUR_PROJECT_ID --config ./supatrace-access.json
  4. Upload the reviewed synthetic example and wait for Accepted by server.
    python3 upload.py ./first-trace.json --config ./supatrace-access.json
  5. Open Traces, select Refresh Traces and open first-trace-example.

The key in supatrace-access.json is a setup-code key: it can upload but cannot read traces, lasts 30 days and can be revoked. Keep the file private. See Keys.

SDK availability Beta

Python SDK: Beta. JavaScript SDK: Coming soon. Install the alpha Python package with pip install supatrace==0.1.0 (Python 3.10+). The JavaScript supatrace package is not published to npm; its examples run from the public repository root. For a first hosted trace, use the stock OpenTelemetry exporter or the Python/Node snippets on Home.

Python

pip install supatrace==0.1.0
import supatrace

trace = supatrace.init(service="checkout", spool="./spool")
result = trace.batch([
    {"id": "e1", "time": "2026-11-14T00:00:00Z", "kind": "note", "name": "hello", "data": {"message": "safe"}},
])
print(result["report"]["valid"], result["report"]["path"])

JavaScript

npm install ./packages/supatrace-js   # from the public repository root. Node 22 or later, ESM only
import { init } from "supatrace";

const trace = init("checkout", { spool: "./spool" });
const result = trace.batch([
  { id: "e1", time: "2026-11-14T00:00:00Z", kind: "note", name: "hello", data: { message: "safe" } },
]);
console.log(result.report.valid, result.report.path);

Both write the same file for the same batch: spool/<sha256>.json. An event has an id, a time, a kind (request, tool_call, tool_result, response, error or note), a name and a data object. Pass dry_run=True (Python) or dryRun: true (JavaScript) to validate without writing.

import supatrace

trace = supatrace.init(service="checkout", spool="./spool")
report = trace.batch([{"id": "e1", "time": "2026-11-14T00:00:00Z", "kind": "note", "name": "hello", "data": {}}], dry_run=True)["report"]
print(report["valid"], report["errors"], report["path"])

Review, then upload

Open the spooled file and read it. Remove anything you do not intend to store. Then upload it with the script from the setup guide, using the write-only connection you approved there:

python3 upload.py ./spool/BATCH.json --config ./supatrace-access.json

The trace appears under Traces in your workspace. Batch limits apply: 100 events and 512 KiB per batch.

Traces can contain prompts, tool output and secrets. Review before upload.
