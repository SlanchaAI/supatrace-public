Providers used by SupaTrace

Slancha, Inc. uses the following providers for the stated service functions. Authentication, billing and DNS providers do not receive customer trace content from SupaTrace. Their role is limited to the function described; customer-selected import sources and export destinations are separate from this list.

ProviderFunction and information
Amazon Web Services (AWS)Hosting, delivery and storage through CloudFront, Lambda, S3 and DynamoDB; account/session metadata, trace payloads, diagnostics and backups. The deployment region is us-east-1, United States; CloudFront provides global delivery. AWS SES sends authentication and service email and receives support email, processing addresses and message content.
StripeCheckout, subscriptions, invoices and payment processing; billing contact, organization/customer references, payment and usage information. Stripe processes subscription payments and approved usage charges. Trace content is not sent to Stripe.
GitHubGitHub OAuth authentication using user:email; account identity and verified email, authentication requests and associated provider metadata. No trace content is sent for sign-in.
GoogleGoogle OAuth authentication using openid email; account identity and verified email, authentication requests and associated provider metadata. No trace content is sent for sign-in.
CloudflareDNS for SupaTrace domains. DNS query metadata; no customer trace payloads are sent for this function.

Customer-directed integrations

When you authorize a provider import, SupaTrace reads the exact source scope you select using the credentials you enter at runtime. Customer-selected trace providers are your sources, not general subprocessors appointed by Slancha. Likewise you choose destinations for exports and trace drains. Review those providers' terms before authorizing transfer.
